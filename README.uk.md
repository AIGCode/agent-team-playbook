# team-playbook - як користуватися

Працюю зі штучним інтелектом від самої його появи і весь час намагаюся вбудувати його так, щоб роботи стало менше або щоб устигати більше. Роботи поки менше не стало, а от продуктивність зросла в рази.

Головна проблема, з якою я боровся: чати не передають інформацію один одному. Усі ці режими стискання листування під час переходу в нову сесію працюють погано - щось обов'язково губиться. Тому я почав працювати проєктами: усі ухвалені рішення й домовленості зберігаються у файлах проєкту, а не в пам'яті чату. Закрив чат - нічого не зникло, новий чат продовжує з того самого місця.

Потім уперся в наступне: один чат не витягує великий проєкт цілком. Довелося роздати роботу агентам - у кожного своя роль (розробник, перевіряльник тощо), і продумати, як вони передають один одному дані. Так з'явився team-playbook. Усе перевірено на звичайній підписці Claude Max 5x (107 євро на місяць), і весь час на найновіших моделях: починав із GPT і Claude, зараз працюю на Claude Code Opus 5.5 у Visual Studio Code. Для тих, хто працює в Cursor, є окремий файл `team/RUN_CURSOR.md`: це інструкція для ШІ - за нею він запускає агентів команди вже засобами Cursor, а сама робота йде так само.

Які задачі так розв'язую? Від простих ланцюжків листів на одну тему до складних застосунків. Наприклад, зараз пишу конектор між Zoho CRM, Shopify та Reverb (найтоповіший маркетплейс для перепродажу гітар, щось на зразок eBay).

Встанови його і почни свій перший проєкт - нижче все по кроках.

## Встановлення

Папку `team-playbook/` покласти в `~/.claude/team-playbook/`. Це каркас - папка-джерело, а не проєкт: з неї скіли беруть команду і шаблони при кожному новому проєкті. Можна покласти й в інше місце - тоді `team-init` (він бере з каркаса команду і шаблони) запитає шлях до нього. Скіли з `skills/` скопіювати в `~/.claude/skills/`, по папці на скіл.

> Промпти ролей і складність завдань розраховані на моделі класу Opus 4.8 і вище. На слабших моделях якість не гарантується. Каркас написаний під Claude Code. Якщо працюєш з іншим інструментом чи моделлю, попроси її знайти в каркасі зв'язки з Claude Code і адаптувати їх під себе.

## Старт роботи

**Проєкту ще немає.**
1. Базовий ресерч: зібрати вихідну інформацію по задачі.
2. `project-init`: оформити проєкт.
3. `team-init`: розгорнути команду.
4. `new-role`: якщо твій стек не PHP - переписати ролі під стек проєкту.

**Проєкт є.**
1. Відкрити новий чат, віддати `AGENTS.md` проєкту: «Працюємо в цьому проєкті».
2. Віддати файл ролі: «Це твоя роль, скажи, як ти її зрозумів».
3. Якщо це роль Tech Lead-а (`team/roles/techlead.md`), він доповідає, як зрозумів роль, і веде роботу за workflow. Якщо інша роль, це коротка робота в межах проєкту без Tech Lead-а.

## Життєвий цикл

```
Задача
  -> ресерч: зібрати, що відомо
  -> проєкт: матеріали і рішення зберігаються в одному місці
  -> команда: підключається, коли задача виросла
  -> архітектура: якщо є що тримати
  -> місії по колу:
       контракт -> робота -> перевірка -> приймання -> закриття
       (план і рішення проєкту оновлюються після кожної)
  -> проєкт завершено
```

Команду відклали - розгорнути пізніше скілом `team-init`.

## Що всередині

- `team/` - каркас команди: ролі (`roles/`), ланцюг місії (`workflow.md`), запуск агентів (`RUN.md`), шаблони (контракт, завдання, питання користувачу, деплой, канон архітектури, безпека - `security-template.md` і PHP-приклад `security-example.md`), оцінювання звітів. Плейсхолдери (`<project>`, `<app>`, `<SERVER_ROOT>`, `[короткий опис проєкту]`, «Локальне середовище» у Developer-а і Tester-а) заповнюються під конкретний проєкт; якщо стек проєкту не PHP, одного заповнення мало - ролі ще переписуються під стек (див. `TEAM.md`, «Ролі»).
- `skills/` - три скіли:
  - `project-init` - створити й організувати новий проєкт (структура файлів).
  - `team-init` - розгорнути команду в проєкті з каркаса.
  - `new-role` - створити нову роль команди або переписати наявну під свій стек.
- `TEAM.md` - принципи роботи команди (прочитати перед першою місією).

## Що почитати далі

1. `README.md` (цей файл) - що де лежить.
2. `TEAM.md` - принципи: ланцюг, ролі, гейти, правила.
3. `team/roles/` - ролі, робочий зразок під PHP (developer, checker, reviewer, tester, researcher, architect, techlead); під свій стек їх переписують скілом `new-role`.
4. `team/workflow.md` і `team/RUN.md` - механіка місії та запуску.

Далі - за посиланнями всередині цих файлів: де тема розібрана докладніше в іншому документі, там стоїть посилання на нього.

---

> **Дисклеймер.** Приклади та шаблони в цьому наборі ілюстративні - це не реальні конфігурації і не готові рішення «на 100%». За безпеку, дані та гроші своїх застосунків відповідаєте ви самі й самі набираєте потрібний обсяг правил. Перевіряйте все під свій проєкт: помилка може коштувати даних, грошей або вашої роботи.
