# team-playbook - як користуватися

Переносний каркас команди AI-агентів плюс скіли для роботи з проєктами. Звідси команда розгортається в будь-який проєкт.

> Промпти ролей і складність завдань розраховані на моделі класу Opus 4.8 і вище. На слабших моделях якість не гарантується.

## Що всередині

- `team/` - каркас команди: ролі (`roles/`), ланцюг місії (`workflow.md`), запуск агентів (`RUN.md`), шаблони (контракт, завдання, деплой), оцінювання звітів. Плейсхолдери (`<project>`, `<app>`, `<SERVER_ROOT>`) заповнюються під конкретний проєкт.
- `skills/` - три скіли:
  - `project-init` - створити й організувати новий проєкт (структура файлів).
  - `team-init` - розгорнути команду в проєкті з каркаса.
  - `new-role` - створити нову роль команди.
- `TEAM.md` - принципи роботи команди (прочитати перед першою місією).

## Життєвий цикл

```
Новий проєкт
  -> skill project-init: створити проєкт, запитати "команда зараз чи пізніше?"
  -> skill team-init: розгорнути team/ у проєкт, заповнити плейсхолдери
  -> новий чат = Tech Lead: віддати йому team/roles/techlead.md;
     він підтверджує, як працюватиме сам і з командою
  -> робота: Tech Lead веде місії
     (контракт -> Developer -> Checker -> Reviewer -> Tester -> деплой)
```

Команду відклали - розгорнути пізніше скілом `team-init`.

## З чого почати (новому співробітникові)

1. `README.md` (цей файл) - що де лежить.
2. `TEAM.md` - принципи: ланцюг, ролі, гейти, правила.
3. `team/roles/` - ролі як живі приклади (developer, checker, reviewer, tester, researcher, architect, techlead).
4. `team/workflow.md` і `team/RUN.md` - механіка місії та запуску.

Далі заглиблюватися за посиланнями.
